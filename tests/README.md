# Tests

GDScript tests use GUT only in development/CI. GUT is fetched from its official upstream at the commit pinned by `tools/ci/install_gut.sh`; the addon is ignored by Git and removed before export so it is not shipped in desktop/Android artifacts.

## Gameplay acceptance contract (2026-11-26)

Baseline inspected: 7ad98e1b9644fd8d70869ad46c24d6b05d8a2a67. Existing CI green does not establish gameplay acceptance. Source-string checks (e.g. timer text, export config) are static checks; calling a controller's private input handler, emitting pressed manually, teleporting the motor, or using fixture-only state is integration/component evidence, not player input evidence. Keep these checks; never count them as device or full-loop acceptance.

**Evidence labels:** STATIC, UNIT, COMPONENT, PACKED_RUNTIME, EXPORTED_DESKTOP, ANDROID_DEVICE, TWO_DEVICE_LAN. Each scenario must report exact code SHA, test ID, seed, environment, input trace, expected and observed state, duration, failure reason, and relevant screenshot/video/trace. Missing evidence = NOT RUN; timeout, script error, missing test, vacuous assertion or unexpected rejection = FAIL. Do not substitute marker strings for assertions. No real saves or live accounts; use isolated user:// and disposable rooms. No gameplay tuning to make tests pass.

The corresponding acceptance test must fail. Restore original source byte-for-byte; never commit mutants. Report killed/surviving mutants individually. Not yet executed.

Passing all existing tests or adding a matrix row is not completion. Test coverage and current status are reported per scenario and evidence level, not by assertion count.

## Rendered player behavior QA

Separate workflow `visual-player-qa.yml` runs seven independently seeded scripted player profiles against the shipped Bootstrap scene using the actual Godot input dispatch, physics and Compatibility renderer in Xvfb. Navigator, reverse, edges, spam, explorer, duelist and reckless each have isolated saves; they are independent simulated players, not seven concurrent network peers. Each 15–20 simulated-second session captures actual viewport pixels at 5 FPS, saves an MP4, all-frame contact sheets and action/physics/damage JSON. The software renderer is not an Android performance test. Failed routes or missing combat evidence fail that profile without hiding its evidence. Visual review is separate from the automatic pass: inspect actual frames for bow alignment, sprite snapping, coast clipping, HUD overlap, and visible firing/hit feedback; no drawn trajectory substitute. Missing VFX and controls are findings, not presumed successes. Existing GUT/LAN/export gates remain unchanged.
